## 1. Executive Summary & Core Principles

Translating content while leaving URL slugs in English harms international SEO and conversion rates. When translating URL slugs, naive implementations cause **catastrophic database data loss**, **route collisions in SSG frameworks**, **404 broken links in rich text**, and **search engine penalties due to redirect chains**.

### The 5 Ironclad Rules
1. **Never drop the root slug column before copying data**: Default DDL migrations generated by Payload CLI drop the unlocalized column immediately.
2. **Never apply Latin-only Unicode normalization (NFD) to non-Latin alphabets**: NFD strips crucial letters in Russian (`й` becomes `и`) and breaks Arabic letters (`كيف يؤدي` turns into `كيف-يو-دي`).
3. **Never translate item slugs without localizing parent prefixes**: Having `/ar/blog/مكيف-سبليت` is an incomplete translation; it must be `/ar/المدونة/مكيف-سبليت`.
4. **Never alter the `home` slug**: The homepage slug must remain strictly `'home'` (or empty) across all locales.
5. **Always preserve global singletons in Schema.org**: Entities like `#organization`, `#website`, and `#logo` must remain global to consolidate domain authority in Google Knowledge Graph.

## 2. Database Architecture & The 3-Phase Migration Rule

### The PostgreSQL Storage Model in Payload 3.x
When a field is changed from `localized: false` to `localized: true`:
- **Unlocalized field**: Stored on the parent table (`pages.slug`, `blog.slug`, `products.slug`).
- **Localized field**: Moves to the locale table (`pages_locales.slug`, `blog_locales.slug`, `products_locales.slug`) with foreign key `_parent_id -> id` and column `_locale`.
- **Drafts & Versions**: Moves to `_[collection]_v_locales.version_slug`.

### The Catastrophic Failure Risk
Running `payload migrate:create` produces DDL like:
```sql
-- DANGEROUS DEFAULT PAYLOAD CLI OUTPUT
ALTER TABLE "pages_locales" ADD COLUMN "slug" varchar;
ALTER TABLE "pages" DROP COLUMN "slug"; -- ⚠️ ALL DATA PERMANENTLY DESTROYED!
```
If executed, all existing slugs are dropped before data is copied.

### The Mandatory 3-Phase Migration Protocol

Every slug localization migration **must** be manually rewritten into three discrete, verifiable phases inside a single transaction:

```typescript
import { MigrateUpArgs, MigrateDownArgs, sql } from '@payloadcms/db-postgres';

export async function up({ payload, req }: MigrateUpArgs): Promise<void> {
  await payload.db.drizzle.execute(sql`
    BEGIN;

    -- =========================================================================
    -- PHASE A: DDL - Add target columns to locale & version tables
    -- =========================================================================
    ALTER TABLE "pages_locales" ADD COLUMN IF NOT EXISTS "slug" varchar;
    ALTER TABLE "blog_locales" ADD COLUMN IF NOT EXISTS "slug" varchar;
    ALTER TABLE "products_locales" ADD COLUMN IF NOT EXISTS "slug" varchar;
    ALTER TABLE "solutions_locales" ADD COLUMN IF NOT EXISTS "slug" varchar;

    ALTER TABLE "_pages_v_locales" ADD COLUMN IF NOT EXISTS "version_slug" varchar;
    ALTER TABLE "_blog_v_locales" ADD COLUMN IF NOT EXISTS "version_slug" varchar;

    -- =========================================================================
    -- PHASE B: DATA PRESERVATION & BACKFILL
    -- =========================================================================
    -- 1. Ensure an 'en' locale row exists for all parent records
    INSERT INTO "pages_locales" ("_parent_id", "_locale", "slug")
    SELECT p."id", 'en', p."slug"
    FROM "pages" p
    ON CONFLICT ("_parent_id", "_locale") DO UPDATE 
    SET "slug" = EXCLUDED."slug" WHERE "pages_locales"."slug" IS NULL;

    -- 2. Backfill existing non-EN locale rows with the English slug as base
    UPDATE "pages_locales" pl
    SET "slug" = p."slug"
    FROM "pages" p
    WHERE pl."_parent_id" = p."id" AND pl."slug" IS NULL;

    -- Repeat for blog, products, solutions, and version tables:
    UPDATE "blog_locales" bl
    SET "slug" = b."slug"
    FROM "blog" b
    WHERE bl."_parent_id" = b."id" AND bl."slug" IS NULL;

    UPDATE "_pages_v_locales" pvl
    SET "version_slug" = pv."version_slug"
    FROM "_pages_v" pv
    WHERE pvl."_parent_id" = pv."id" AND pvl."version_slug" IS NULL;

    -- =========================================================================
    -- PHASE C: CONSTRAINTS & DROP OLD COLUMNS
    -- =========================================================================
    -- Add compound unique indexes per locale
    CREATE UNIQUE INDEX IF NOT EXISTS "pages_locales_locale_slug_idx" 
      ON "pages_locales" ("_locale", "slug");
    CREATE UNIQUE INDEX IF NOT EXISTS "blog_locales_locale_slug_idx" 
      ON "blog_locales" ("_locale", "slug");
    CREATE UNIQUE INDEX IF NOT EXISTS "products_locales_locale_slug_idx" 
      ON "products_locales" ("_locale", "slug");
    CREATE UNIQUE INDEX IF NOT EXISTS "solutions_locales_locale_slug_idx" 
      ON "solutions_locales" ("_locale", "slug");

    -- Drop legacy unlocalized columns ONLY AFTER Phase B verification
    ALTER TABLE "pages" DROP COLUMN IF EXISTS "slug";
    ALTER TABLE "blog" DROP COLUMN IF EXISTS "slug";
    ALTER TABLE "products" DROP COLUMN IF EXISTS "slug";
    ALTER TABLE "solutions" DROP COLUMN IF EXISTS "slug";
    ALTER TABLE "_pages_v" DROP COLUMN IF EXISTS "version_slug";
    ALTER TABLE "_blog_v" DROP COLUMN IF EXISTS "version_slug";

    COMMIT;
  `);
}

export async function down({ payload, req }: MigrateDownArgs): Promise<void> {
  // Always write symmetric down migration copying 'en' slug back to root column
  await payload.db.drizzle.execute(sql`
    ALTER TABLE "pages" ADD COLUMN IF NOT EXISTS "slug" varchar;
    UPDATE "pages" p SET "slug" = pl."slug" FROM "pages_locales" pl WHERE pl."_parent_id" = p."id" AND pl."_locale" = 'en';
    ALTER TABLE "pages_locales" DROP COLUMN IF EXISTS "slug";
  `);
}
```

## 3. Slug Generation & Unicode Handling (Latin vs. Non-Latin)

### The Unicode Pitfall in Non-Latin Locales
A common mistake in Node.js slugifiers is applying `text.normalize('NFD').replace(/[\u0300-\u036f]/g, '')`.
- **Russian**: Decomposes `й` (`\u0439`) into `и` + `\u0306`. The regex strips `\u0306`, corrupting `инверторный` into `инверторныи`.
- **Arabic**: Decomposes `ؤ`, `إ`, `أ`, `ئ` into base letters and Arabic combining marks. When regex replaces non-word characters, words break into fragmented hyphens (e.g., `كيف يؤدي` becomes `كيف-يو-دي`).

### The Production-Grade Universal Slugifier
Use the standard engine from `@itpyx/payload-auto-translate`:

```typescript
const GERMAN_UMLAUTS: Record<string, string> = {
  ä: 'ae', ö: 'oe', ü: 'ue', Ä: 'ae', Ö: 'oe', Ü: 'ue', ß: 'ss',
};

const NON_LATIN_LOCALES = new Set(['ar', 'ja', 'zh', 'ru', 'he', 'fa', 'ko', 'th', 'hi']);

export function slugifyTitle(
  title: string,
  locale: string,
  options: { latinOnly?: boolean; maxLength?: number } = {}
): string {
  if (!title || typeof title !== 'string') return '';
  const maxLength = options.maxLength || 90;

  // 1. If Latin-only mode is enforced and locale is non-Latin, return unchanged base slug
  if (options.latinOnly && NON_LATIN_LOCALES.has(locale)) {
    return '';
  }

  // 2. Non-Latin handling: Preserve Unicode letters and numbers using NFC
  if (NON_LATIN_LOCALES.has(locale)) {
    let clean = title
      .normalize('NFC')
      // Strip Arabic tashkeel vocalization marks
      .replace(/[\u064B-\u065F\u0670]/g, '')
      // Strip punctuation and quotes
      .replace(/["'’“”«»()\[\]{}.,;:!?]/g, ' ')
      // Convert any sequence of non-letter/number characters to hyphens
      .replace(/[^\p{L}\p{N}]+/gu, '-')
      .replace(/^-+|-+$/g, '')
      .toLowerCase();

    // Clamp length without breaking Unicode characters
    if (clean.length > maxLength) {
      const idx = clean.lastIndexOf('-', maxLength);
      clean = idx > 20 ? clean.slice(0, idx) : clean.slice(0, maxLength);
    }
    return clean;
  }

  // 3. Latin handling: Expand German umlauts, strip diacritics
  let text = title;
  if (locale === 'de') {
    text = text.replace(/[äöüÄÖÜß]/g, (c) => GERMAN_UMLAUTS[c] || c);
  }

  let slug = text
    .normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '') // Strip accents safely in Latin
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');

  if (slug.length > maxLength) {
    const idx = slug.lastIndexOf('-', maxLength);
    slug = idx > 20 ? slug.slice(0, idx) : slug.slice(0, maxLength);
  }

  return slug;
}
```

## 5. Frontend Routing Architecture & Astro/Next.js Patterns

### Resolving Route Collisions in SSG
In Astro, having static routes like `pages/[lang]/blog/index.astro` alongside dynamic `pages/[lang]/[slug].astro` causes build collision errors in European languages where `blog` is identical to English (`es`, `fr`, `de`, `it`, `pt`).

#### The Unified SSG Architecture
1. **Single-Segment Routes**: Handled by `apps/web/src/pages/[lang]/[slug].astro`:
   - Matches products, archive pages (`blog`, `solutions`, `products`), and content pages (`about`, `contact`, `certifications`, `quality`, `faq`).
2. **Two-Segment Dynamic Routes**: Handled by `apps/web/src/pages/[lang]/[section]/[slug].astro`:
   - Handles both `solutions` items (`/${lang}/${localizedSolutionsParent}/${solutionSlug}`) and `blog` posts (`/${lang}/${localizedBlogParent}/${postSlug}`).
   - Delete individual `[lang]/blog/[slug].astro` and `[lang]/solutions/[slug].astro` folders.
   - Retain default English routes (`pages/blog/[slug].astro`, `pages/solutions/[slug].astro`).

```astro
---
// apps/web/src/pages/[lang]/[section]/[slug].astro
export async function getStaticPaths() {
```

### Universal `localizePath` Helper
The URL localizer must resolve internal canonical paths into localized URLs:

```typescript
export function localizePath(path: string, locale: Locale): string {
  if (!path || path.startsWith('http://') || path.startsWith('https://') || path.startsWith('//')) {
    return path;
  }

  const cleanPath = path.replace(/^\/+|\/+$/g, '');
  if (!cleanPath) return locale === 'en' ? '/' : `/${locale}`;

  const parts = cleanPath.split('/');

  // 1. Handle single-segment archive or page
  if (parts.length === 1) {
    const canonicalKey = reversePageSlugMap.get(parts[0]) || parts[0];
    const targetSlug = pageSlugMap[canonicalKey]?.[locale] || parts[0];
    return locale === 'en' ? `/${targetSlug}` : `/${locale}/${targetSlug}`;
  }

  // 2. Handle two-segment routes (blog or solutions)
  if (parts.length === 2) {
    const parentKey = reversePageSlugMap.get(parts[0]) || parts[0];
    const targetParent = pageSlugMap[parentKey]?.[locale] || parts[0];

    if (parentKey === 'blog') {
      const canonicalPostSlug = getCanonicalBlogSlug(parts[1]);
      const targetPostSlug = blogSlugMap[canonicalPostSlug]?.[locale] || parts[1];
      return locale === 'en' ? `/blog/${targetPostSlug}` : `/${locale}/${targetParent}/${targetPostSlug}`;
    }

    if (parentKey === 'solutions') {
      const canonicalSolSlug = getCanonicalSolutionSlug(parts[1]);
      const targetSolSlug = solutionSlugMap[canonicalSolSlug]?.[locale] || parts[1];
      return locale === 'en' ? `/solutions/${targetSolSlug}` : `/${locale}/${targetParent}/${targetSolSlug}`;
    }
  }

  return locale === 'en' ? `/${cleanPath}` : `/${locale}/${cleanPath}`;
}
```

## 6. Lexical Rich-Text & Hardcoded Component Link Sanitization

### 1. Bare Domains & Relative Path Traps
In rich text (Lexical JSON AST), content authors often insert links as `iclimaair.com` or `/blog/post-name`.
- A link to `iclimaair.com` rendered on `/ar/blog` becomes relative: `<a href="iclimaair.com">`, resolving in the browser to `https://www.iclimaair.com/ar/blog/iclimaair.com` (404 Error!).
- **Renderer Fix**:
  ```typescript
  // Normalize internal domain references
  const DOMAIN_REGEX = /^(?:https?:\/\/)?(?:www\.)?example\.com(\/.*)?$/i;
  if (DOMAIN_REGEX.test(url)) {
    const match = url.match(DOMAIN_REGEX);
    url = match?.[1] || '/';
  }
  return localizePath(url, lang);
  ```

### 2. Machine Translation Protocol Corruption
Machine translation engines often translate URL protocol prefixes:
- `mailto:nora@example.com` ➔ translated to `correo a: nora@example.com` or `ميلتو: ...`
- `tel:+8617786855861` ➔ translated to `الهاتف: +8617786855861`
When placed in `<a href={card.link_url}>`, browsers treat them as relative URLs and append the current page path, resulting in 404 errors like `/ar/الهاتف: +8617786855861`.
- **Sanitizer Fix**:
  ```typescript
  export function normalizeContactLink(url: string, title?: string): string {
    if (!url) return '';
    const clean = url.trim();
    if (clean.includes('@') && !clean.startsWith('mailto:')) {
      return `mailto:${clean.replace(/^(mailto:\s*|correo a:\s*|ميلتو:\s*)/i, '').trim()}`;
    }
    if (/[\d+]{7,}/.test(clean) && !clean.startsWith('tel:') && !clean.startsWith('http')) {
      return `tel:${clean.replace(/^[^\d+]+/, '').trim()}`;
    }
    return clean;
  }
  ```

## 7. SEO 301 Redirection & Chain-Flattening Strategy

### The 4 Mandatory 301 Redirect Rules
When migrating existing URLs to localized slugs, insert 301 redirects into Payload's `redirects` table:
1. **Unlocalized segment under locale**:
   `/${locale}/${enSlug}` ➔ `/${locale}/${localizedSlug}`
2. **Unlocalized parent segment under locale**:
   `/${locale}/solutions/${localizedSlug}` ➔ `/${locale}/${localizedSolutionsParent}/${localizedSlug}`
   `/${locale}/blog/${enSlug}` ➔ `/${locale}/${localizedBlogParent}/${localizedSlug}`
3. **Cross-locale links lacking locale prefix**:
   `/solutions/${localizedSlug}` ➔ `/${locale}/${localizedSolutionsParent}/${localizedSlug}`
4. **Historical Draft / Typo Slugs**:
   Map short draft slugs (`air-conditioner-leaking-water-inside`) across all 9 locales directly to the final published canonical slugs (`why-is-my-air-conditioner-leaking-water-inside-causes-fixes`).

### Redirect Chain Flattening Algorithm
Search engines penalize multi-hop redirects. Flatten all redirect chains before deployment:

```typescript
export function flattenRedirectChains(
  redirects: Array<{ from: string; to: string }>
): Array<{ from: string; to: string }> {
  const map = new Map<string, string>();
  for (const r of redirects) {
    map.set(r.from, r.to);
  }

  return redirects.map(({ from, to }) => {
    let current = to;
    const visited = new Set<string>([from]);

    while (map.has(current)) {
      const next = map.get(current)!;
      if (visited.has(next)) break; // Prevent circular redirect loops
      visited.add(next);
      current = next;
    }

    return { from, to: current };
  });
}
```

In `sitemap-products.xml.ts`, `sitemap-solutions.xml.ts`, and `sitemap-blog.xml.ts`:
- Fetch docs across all locales with `limit=100&depth=0`.
- Group by document ID (`doc.id`).
- For each item, output `<url>` containing child `<xhtml:link rel="alternate" hreflang="..." href="..." />` tags for all 9 locales.
- **Strict Canonical Rule**: Canonical URLs must **never** contain trailing slashes if the site policy is `trailingSlash: false` (`https://www.example.com/es` NOT `https://www.example.com/es/`).

## 9. Dynamic Schema.org JSON-LD Localization

When pages feature custom Schema.org data (`meta.schema`), URLs within the JSON-LD must reflect the active locale without breaking Schema syntax.

### The 3 Rules of Schema.org Localization
1. **Preserve Global Singletons**:
   - Organization: `https://www.example.com/#organization`
   - Website: `https://www.example.com/#website`
   - Logo: `https://www.example.com/#logo`
   These **must remain constant** across all languages so Google consolidates knowledge graph authority into a single brand entity.
2. **Localize Document Entities**:
   - WebPage: `https://www.example.com/es#webpage`
   - PrimaryImage: `https://www.example.com/es#primaryimage`
   - Internal URLs (`url`, `item`): Map to localized page and product URLs.
3. **Whitelist Copy for Translation**:
   Translate natural text (`Question.name`, `Answer.text`, `description`, `name`, `headline`) while preserving `@context`, `@type`, and Schema enums (`https://schema.org/InStock`).

## 10. Step-by-Step Reusable Implementation Blueprint

Follow this exact sequence when implementing slug localization on a new project:

### Phase 1: Preparation & Schema Updates (Day 1)
- [ ] Run full database backup: `pg_dump -Fc > backup_pre_slug.dump`
- [ ] In Payload collections (`Pages.ts`, `Blog.ts`, `Products.ts`), set `localized: true` on the `slug` field.
- [ ] Generate migration: `npx payload migrate:create add_localized_slugs`.
- [ ] **Rewrite migration**: Split into Phase A (DDL), Phase B (Data Copy & Assert), Phase C (Unique Indexes & Drop legacy column).
- [ ] Run migration: `npx payload migrate`. Verify 0 null slugs across all locales.

### Phase 2: Plugin Configuration (Day 1)
- [ ] Install `@itpyx/payload-auto-translate@^1.2.0`.
- [ ] Configure `payload.config.ts`:
  ```typescript
  autoTranslatePlugin({
    engine: { url: process.env.LIBRETRANSLATE_URL, apiKey: process.env.LIBRETRANSLATE_API_KEY },
    sourceLocale: 'en',
    targetLocales: ['es', 'fr', 'ar', 'pt', 'de', 'ru', 'ja', 'it'],
    slug: { enabled: true, latinLocalesOnly: false, sourceField: 'title' },
    schema: { enabled: true, siteUrl: 'https://www.example.com', syncOverrideFlag: true },
    customFieldExclusions: ['meta_schema', 'meta_override_default_schema'],
  })
  ```

### Phase 3: Frontend Route Architecture (Day 2)
- [ ] Define canonical dictionaries in `src/lib/i18n.ts` (`pageSlugMap`, `productSlugMap`, `solutionSlugMap`, `blogSlugMap`).
- [ ] Update `localizePath` to handle single-segment and two-segment paths.
- [ ] Unify dynamic routes into `[lang]/[slug].astro` and `[lang]/[section]/[slug].astro`.
- [ ] Delete conflicting duplicate static folders (e.g. `[lang]/blog/`, `[lang]/solutions/`).
- [ ] Update rich text renderer to pass links through `localizePath`.

### Phase 4: SEO Defense & Verification (Day 2)
- [ ] Populate 301 redirects in Payload's `redirects` collection for all legacy English paths.
- [ ] Run redirect chain flattener and export to `redirects.json` / `nginx-redirects.conf`.
- [ ] Update sub-sitemaps with multilingual `xhtml:link` hreflang tags.
- [ ] Clear CMS build cache (`rm -rf .astro/cms-cache`).
- [ ] Run production static build and inspect generated HTML files in `.vercel/output/static/`.

## 11. Failure Modes & Troubleshooting Reference

| Issue / Symptom | Root Cause | Resolution |
| :--- | :--- | :--- |
| **All existing slugs disappear after migration** | Payload CLI dropped the root `slug` column before data copy. | Revert from SQL backup; execute the 3-Phase Migration Protocol. |
| **Arabic / Russian slugs are mangled with hyphens (`كيف-يو-دي`)** | `normalize('NFD')` stripped combining letters. | Switch to `normalize('NFC')` and Unicode property escape `[^\p{L}\p{N}]+`. |
| **404 error when navigating from `/ar/blog` to an article** | Parent slug `/blog` remained in English while post slug was Arabic. | Localize the parent slug in `pageSlugMap.blog` and unify into `[section]/[slug].astro`. |
| **Phone and email links produce 404 URLs (`/ar/الهاتف: +86...`)** | Machine translation translated `mailto:` or `tel:`. | Wrap card links with `normalizeContactLink()` to enforce valid protocol prefixes. |
| **Astro build error: duplicate route collision in European locales** | Folder `[lang]/blog/` collided with `[lang]/[section]/` when `section === 'blog'`. | Delete `[lang]/blog/` folder; use unified `[section]/[slug].astro` with `props: { type: 'blog' }`. |
| **Google Search Console reports redirect chains (2+ hops)** | Legacy URL redirected to intermediate path before final localized path. | Run `flattenRedirectChains()` on the redirect table before export. |
| **Schema.org Knowledge Graph authority fragmented across languages** | `#organization` or `#website` `@id` was localized to `https://www.example.com/es#organization`. | Enforce `GLOBAL_ENTITY_FRAGMENTS` check in `localizeAbsoluteUrl()` to keep singletons unlocalized. |
| **Stale English schema renders on localized static pages** | Astro built using stale cached CMS data. | Clear `.astro/cms-cache` prior to static production build. |
